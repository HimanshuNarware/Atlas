# Data and Qdrant Model

## 1. Design rule

Separate application metadata, original file storage, and vector search. Qdrant stores vectors and searchable payloads; it should not be treated as the only source of truth for document lifecycle, users, conversations, or original PDF binaries.

The metadata database and object-storage provider are `TBD`.

## 2. Logical entities

### Document

- `id`: stable application ID.
- `ownerId` or tenant scope: who may access it.
- `originalFilename`: sanitized display name.
- `storageKey`: private file-storage key; never a public path by default.
- `mimeType`, `sizeBytes`.
- `pageCount`: nullable until extraction completes.
- `status`: uploaded / processing / ready / failed / deleting / deleted.
- `processingErrorCode`: safe internal code, not a raw provider error.
- `createdAt`, `updatedAt`, `processedAt`.
- `indexVersion`: chunking/embedding configuration version.

### Chunk (logical representation; may be stored as Qdrant payload)

- `pointId`: stable vector point ID.
- `documentId`.
- `ownerId` or tenant scope.
- `chunkIndex`.
- `pageStart`, `pageEnd` or page number, where available.
- `text`.
- `embeddingModel` / `indexVersion`.
- Optional safe metadata such as section heading.

### Conversation (if enabled)

- `id`, `ownerId`, `documentId`, `createdAt`, `updatedAt`.

### Message (if enabled)

- `id`, `conversationId`, `role`, `content`, `createdAt`.
- Assistant messages may reference citation IDs/chunk IDs.
- Decide retention and deletion behavior before storing conversation content.

## 3. Qdrant point payload

Illustrative payload:

```json
{
  "documentId": "doc_123",
  "ownerId": "user_456",
  "chunkIndex": 12,
  "pageStart": 7,
  "pageEnd": 8,
  "text": "Extracted text for this chunk...",
  "indexVersion": "embedding-model-and-chunking-v1"
}
```

The vector itself is generated by the chosen embedding model. Collection vector size and distance metric must match that model; both remain `TBD` until the model is selected.

## 4. IDs and idempotency

- Use stable IDs or deterministic IDs for chunk points where feasible.
- An ingestion retry should upsert the same points rather than duplicate them.
- Re-indexing should use an explicit index version or a controlled replacement process.
- Avoid using sequential, guessable IDs as the only access-control mechanism.

## 5. Deletion

Deleting a document should:
1. Authorize the request.
2. Mark it as deleting or otherwise prevent new queries.
3. Remove its Qdrant points using a precise document filter.
4. Remove the original file.
5. Remove related metadata and conversations/messages according to policy.
6. Verify or reconcile partial failures and retry cleanup safely.
7. Mark deletion complete.

Define a retention policy for backups, logs, and any external AI provider data before launch.

## 6. Payload size

- Chunk extracted text to a bounded size.
- Batch vector upserts.
- Keep payload metadata useful and compact.
- Store the original PDF outside Qdrant.
- Monitor collection size, payload growth, and embedding costs.
